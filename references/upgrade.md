# 업그레이드(버전 패치) — 스킬 폴더와 도서관

이미 wiki-desk를 쓰는 프로젝트가 새 배포 버전을 받을 때의 절차다. 업그레이드는 두 층을 다룬다.

| 층 | 위치 | 업그레이드 때 |
|---|---|---|
| 스킬 폴더 | `<skill-dir>`(호스트별 경로는 [hosts.md](hosts.md)) | 새 배포본으로 **교체** |
| 도서관(위키) | 프로젝트 루트 `<wiki_dir>/`(`__llm-wiki/` 등) — 계약·receipt·카드·색인 | 버전의 **도서관 조치 등급**에 따라 없음·재생성·이관 |

원문(`source_roots`의 문서)은 어떤 업그레이드에서도 대상이 아니다. `docs/`·헌장·`AGENTS.md`·`CLAUDE.md`도 업그레이드가 고치지 않는다.

## 릴리스 호환표
| 올리는 구간 | 계약 `schema_version` | 카드 `okf_version` | 도서관 조치 | 할 일 |
|---|---|---|---|---|
| 2.x → 3.0.x | 1 → 1 | 0.2 → 0.2 | **재생성** | 카드 메타 키 이름이 바뀌었다(이전 카드는 `card.invalid`). 스킬 교체 뒤 `remove --apply` → `sync --apply` |
| 3.0.x → 3.2.0 | 1 → 1 | 0.2 → 0.2 | **이관(계약)** | 계약 `search`에 필수 키 3개 추가, `glossary.json` 추가. 아래 절 |
| 3.2.0 → 3.3.0 | 1 → 1 | 0.2 → 0.2 | **없음** | 스킬 폴더만 교체. 계약·카드·색인 그대로 |

여러 버전을 건너뛰면 사이 구간의 조치를 **오래된 것부터 순서대로** 적용한다(예: 3.0.x → 3.3.0 = 3.0.x→3.2.0 이관 + 3.2.0→3.3.0 없음).

## 사용자 절차
1. **새 버전을 임시 폴더에 푼다.** 기존 스킬 폴더는 건드리지 않는다.
   ```bash
   (
     set -euo pipefail
     SOURCE="/absolute/path/to/wiki-desk"   # 이 저장소의 git clone
     VERSION="v3.3.0"
     STAGE="$(mktemp -d)"
     git -C "$SOURCE" archive "$VERSION" | tar -x -C "$STAGE"
     ( cd "$STAGE" && node scripts/package-manifest.ts --check && node --test )
     printf '새 버전 위치: %s\n' "$STAGE"
   )
   ```
2. **차이를 보고한다.** 기존 `SKILL.md`·새 `SKILL.md`의 `metadata.version`, `diff -r <skill-dir> <STAGE>` 결과(바뀐 파일 목록), 그리고 위 호환표의 해당 구간 조치를 사용자에게 보여 준다. 기존 폴더에 사람이 고친 파일이 있으면 이 diff에 드러난다 — 옮겨 둘지 사용자가 정한다.
3. **승인을 받으면 교체한다.** 승인이 없으면(무응답 포함) 여기서 멈추고 아무것도 바꾸지 않는다.
   ```bash
   mv <skill-dir> <skill-dir>.bak-<이전버전>   # 지우지 않고 보존
   mv <STAGE> <skill-dir>
   ```
4. **도서관 조치를 수행한다.** 등급이 `없음`이면 건너뛴다. `재생성`·`이관`은 반드시 계획(쓰기 0)을 먼저 보고, 승인 뒤 적용한다.
5. **확인한다.** `status`·`check`가 exit 0, 대표 `query` 1건 → 그 ref를 `read`해 원문이 회수되는지. 원문 불변(`git diff --diff-filter=MD -- <source_roots>` 공집합).

**되돌리기**: 스킬은 `<skill-dir>.bak-<이전버전>`을 원래 이름으로 되돌린다. 도서관은 git으로 추적되므로(색인 캐시 제외) 조치 전 커밋으로 되돌린다. 색인 캐시는 파생물이라 지워도 다음 질의 때 다시 만들어진다.

## 3.0.x → 3.2.0 계약 이관
3.2.0은 계약에 `search` 필수 키를 더했다. 검증기는 기본값을 채우지 않으므로, 스킬만 바꾸면 `query`·`check` 등이 누락 키를 알려 주는 오류로 멈춘다(예: `계약 search.match_lines_max: 필수 필드 누락 — 예: "match_lines_max": 20 …`).
1. `<wiki_dir>/contract.json`의 `search`에 `match_lines_max`·`related_max`·`span_group_coverage`를 넣는다. 값은 `assets/project-contract.example.json`의 같은 키를 그대로 쓴다(측정·출하된 기본값).
2. `<wiki_dir>/glossary.json`이 없으면 `assets/glossary.example.json`을 그 이름으로 복사한다(자동 추출 켬).
3. `status`·`check`·`query`가 exit 0인지 확인한다. 카드 형식은 바뀌지 않았으므로 **재입고는 필요 없다**(`sync` 계획의 생성·갱신 0건).

## 2.x → 3.0.x 재생성
스킬 교체 뒤 `sync`로 계획을 보고 `remove --apply` → `sync --apply`로 카드를 다시 만든다. `remove`는 사람이 고친 카드·`contract.json`을 보존하므로, 남은 카드에 이전 키가 있으면 수정분을 옮긴 뒤 직접 지우고 다시 sync한다. 적용 전후 원문 경로 집합이 같은지(누락 0) 확인한다.

## 배포자용 — 패치 설계의 호환 원칙
도서관 재배치·색인 재구조화 같은 형식 변경이 필요하면 **새 버전 방식을 따르되, 기존 도서관과 호환되는 경로**로 설계한다.
1. **조용히 고쳐 쓰지 않는다.** 새 코드는 옛 형식을 그대로 읽거나, 읽을 수 없으면 무엇이 다른지와 이 문서의 절을 가리키는 오류로 멈춘다. 기본값을 몰래 채우거나 카드를 자동 변환하지 않는다.
2. **형식이 바뀌면 버전을 올리고 호환표에 적는다.** 계약 구조는 `schema_version`, 카드·index 형식은 `okf_version`. 구간마다 도서관 조치 등급(없음·재생성·이관)과 할 일을 적는다.
3. **바꾸는 명령은 계획과 적용을 나눈다.** 계획은 쓰기 0, 적용은 `--apply`. 적용 뒤 `check`로 확인할 수 있어야 한다.
4. **보존 규칙은 업그레이드에서도 같다.** 원문은 대상이 아니다. 사람이 고친 카드·`verified` 카드·`protected` 파일은 덮어쓰지 않고 보고한다. 색인 캐시만 자유롭게 다시 만든다.
5. **되돌릴 수 있어야 한다.** 스킬 폴더는 보존 이동, 도서관은 git 커밋 단위로 복구 가능한 범위에서만 바꾼다.
6. **이관 도구는 필요한 버전에서 만든다.** 형식 변경이 없는 버전에 이관 명령을 미리 넣지 않는다.

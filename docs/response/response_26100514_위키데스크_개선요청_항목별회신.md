# 위키데스크 개선요청 항목별 회신

## 현재 판정과 검증 범위

R1~R10을 로컬 배포판 1.1.0에 반영했다. 이 회신은 실제 기능 시험과 요청별 채택 판단을 기록한다. 최종 manifest/설치 복사본의 identity와 독립 검토 종결 증거는 제작 workspace의 별도 release 기록에 결합한다. 이 로컬 검증을 원격 릴리스나 실제 수신 프로젝트 적용으로 읽지 않는다. 실제 수신 프로젝트·운영 위키·profile에는 적용하지 않았다.

- 최종 코드의 전체 `python -B -m pytest tests -q -o addopts='' -p no:cacheprovider`: 322 passed, 170 subtests passed, failed/skip/deselected 0.
- 부모의 실제 설치 CLI: 3host adapter×2wiki 리터럴×2journey = expected/collected/unique 12/12/12 PASS, 192개 CLI 호출.
- 원본 1.0.0 Git archive의 실제 이관, 사용자 위키 보존, checkout 추적 파일 diff0은 suite에 포함한다.
- 발행 측 패치 3편을 원본 1.0.0 사본에 적용한 실제 `1.1.0-vela.2` 설치본에 새 source CLI의 status/query/check/sync-plan/format-check 읽기 호환 PASS, 대상 bytes 변화0.
- 스킬명 없는 한국어 요청 → 새 Claude Code 2.1.287 세션의 `Skill(wiki-desk)` 선택 1회 관측. 수신 측 2.1.289나 모든 host/version의 자동 선택을 인증한 것은 아니다.

여기의 시험 명령은 수신자가 준비한 Python interpreter로 실행한다. 실행 dependency는 PyYAML6, 개발시험은 pytest이며 자동 설치는 하지 않는다. 아래 `CLI`는 source 또는 설치된 전체 패키지의 `scripts/wiki_desk.py`를 뜻한다. 원시 로그는 제작 workspace의 plan에 연결된 evidence에 보존하며 배포판에 private 원문/계정 자료를 넣지 않는다.

## 요청별 회신

### R1 운영 상태 위치와 이관

- 판단: 수정 수용.
- 반영 버전/커밋: 1.1.0 / commit 미생성.
- 반영: `<skill>/project/contract.json`, `receipt.json`; 계약 추적·receipt 비추적; package 인벤토리의 top-level `project/` 제외; installed-self 또는 source 호출 exact-one 상태 탐색; legacy 기본 거부. receipt schema_version=1과 실제 layout 검증 유지. `read_contract(project_root, contract_path)`는 명시 경로이며 bundle 내부 계약을 거부한다.
- 차이: 기존 위키를 지우고 재설치하는 인계 절차 대신 `CLI migrate-state --root TARGET --host HOST`의 기본 write-zero·명시 `--apply` 보존형 이관을 추가했다. VERSION 1.0.0과 원본 manifest·receipt·package bytes가 검증된 설치만 지원한다. 임의 1.0.x나 수정된 local seed를 조용히 교체하지 않는다.
- 수용 기준 확인: 실제 1.0.0 install→migration plan/apply→status→full inverse에서 contract 원본 bytes·위키 bytes/mode·source ID·최초 preimage·sticky 보호를 보존했다. fresh install에 root `.wiki-desk`가 없고 설치본 verify/query/check/sync/format이 통과했다. vela의 동일 상태 배치는 읽기 호환이며 `migrate-state`로 vela 코드까지 자동 업그레이드하지 않는다.

### R2 버전관리된 설치본 재생성

- 판단: 수용.
- 반영 버전/커밋: 1.1.0 / commit 미생성.
- 반영: `CLI rebuild --root TARGET --host HOST` 및 `--apply`. manifest 일치 스킬·계약, receipt·wiki 없음만 받는다.
- 차이: 선택지 중 독립 `rebuild` action을 채택했다. 계약 외 state 추가물도 거부하며 기존 package/contract preimage를 기록해 삭제 권한을 새로 만들지 않는다.
- 수용 기준 확인: 실제 Git checkout-index로 스킬·계약·원문만 내보낸 합성 checkout에서 plan write0, apply 후 `git diff --exit-code`=0, source-registry.json 원 환경과 bytes 동일, status PRESENT. 기존 wiki/receipt와 package tamper는 BLOCKED.

### R3 mode 거짓 DRIFT

- 판단: 수용.
- 반영 버전/커밋: 1.1.0 / commit 미생성.
- 반영: 소유 파일 identity는 hash·size·실행 여부를 비교한다. 트랜잭션 snapshot/readback/rollback은 exact mode를 유지한다.
- 차이: Git과 같은 실행 여부 semantics를 채택했다. 이 기준을 status뿐 아니라 sticky 보호와 제거 검사에도 사용한다.
- 수용 기준 확인: 0644→0664에 status PRESENT, sync 후 보호 표시 없음, full inverse 정상. 실행 여부 변경과 내용 변경에는 DRIFT가 유지된다.

### R4 등록 원문 삭제·이동 조정

- 판단: 수정 수용.
- 반영 버전/커밋: 1.1.0 / commit 미생성.
- 반영: `CLI sync --accept-removed PATH`, `--relocate OLD=NEW`, 반복 지정과 기본 plan/`--apply`. 과거 source 전체 metadata를 append-only `archived_sources`에 reason·offset 시각·이동 목적지와 보존한다. active relocation은 ID·unknown extension 유지.
- 차이: active sources와 별도 history를 구분했고 native planner와 실제 output의 source coverage/transition validator를 함께 확인한다. 원문 파일 자체를 삭제·이동하는 action은 아니다.
- 수용 기준 확인: 기본 missing/scope 차단, 명시 경로만 제거/이동, 2회 이동 후 삭제 이력 누적, ID 보존, metadata/history 변조·중복·collision·escape·excluded/filtered destination·미해결 다른 missing에 write-zero 거부. 설치본 6개 조합에서도 실제 CLI 여정 통과.

### R5 receipt 없는 기존 위키 채택

- 판단: 수용.

- 반영: `CLI adopt --root TARGET --host HOST --contract CONTRACT` 및 `--apply`. 기존 wiki bytes/mode를 바꾸지 않고 모든 파일을 preimage·사용자 보호로 등록한다.
- 차이: 설치 스킬은 missing 목적지 또는 현재 manifest와 정확히 일치하는 복사본만 사용한다. 채택과 형식 교정을 분리했다.
- 수용 기준 확인: CRLF Markdown·binary·임의 mode·empty dir를 가진 기존 위키 전체 bytes/mode 보존, status PRESENT, full remove BLOCKED, 일반 remove 후 wiki 동일. 배포 원본과 skill 목적지의 proper ancestor/descendant 중첩은 plan/apply 전에 거부하며, 검증된 기존 설치본인 exact equality는 허용한다. PRESENT가 OKF/의미상 승인 PASS라는 뜻은 아니다.

## 보존과 한계

독립 품질 검토가 adopt의 source-package/skill proper overlap 누락 1건을 재현했다. 배포 원본 오염은 실제 결함이며 기존 green suite로 무시하지 않았다. 부모가 ancestor(hermes/claude)·descendant write-zero와 equality 성공 회귀를 RED로 확인한 뒤 preflight guard를 교정했다. 교정 회귀 3건·2subtests 및 최종 전체322건·170subtests가 통과했다. 원 결함/RED와 초기 설치 fixture의 보수적 DRIFT 거부 기록은 보존한다.

- 원문 body 복사·과거 승인 재작성·semantic approval 생성·host 권한 완화 없음.
- 일반 remove도 owned DRIFT가 남으면 보수적으로 거부한다. 이미 적합한 사용자 편집을 format/sync가 변경하지 않았다면 옛 receipt hash가 남아 DRIFT일 수 있다. 보호 표시 또는 최신 hash를 삭제 권한으로 해석하지 않는다.
- Windows/macOS native, hostile concurrent writer, process-crash atomicity는 미검증이며 보장하지 않는다.
- 원격 release/tag/commit/push와 실제 운영 적용은 이 결과에 포함하지 않는다.
